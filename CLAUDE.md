# CLAUDE.md

Static, prerendered Angular 21 catalogue site for P K Guled Ilkal Sarees (Ilkal, Karnataka, since 1875). No backend: every route is a plain HTML file served by nginx, all content comes from JSON, and the only conversion path is WhatsApp. README.md covers content editing for the owner; DEPLOY.md covers the Ubuntu VM. This file is for working on the code.

## Commands

```bash
npm run images        # image pipeline only (raw-images/ -> public/img + catalog JSON)
npm run build         # prebuild (images) -> ng build (prerender) -> postbuild (sitemaps, 404, CSP)
npx ng build          # Angular build only, skips the image + postbuild steps (fast check)
npm run serve:static  # serve dist/pkguled-web/browser on :4300 (no gzip, redirects dirs to trailing slash)
npm start             # dev server :4200
HOST_PORT=8082 docker compose up -d --build   # how the owner deploys on the VM (8080 is blocked there)
```

`npm run build` must finish with zero warnings. Check with `npm run build 2>&1 | grep -E "WARNING|ERROR|Prerendered"`. Expect `Prerendered 19 static routes` and `570 product images across 14 categories`.

There are no meaningful unit tests (the scaffold spec was removed). Verify changes by building and inspecting the prerendered HTML in `dist/pkguled-web/browser/`, or by driving Chrome (installed at `C:/Program Files/Google/Chrome/Application/chrome.exe`) with puppeteer-core from a scratch folder.

## Hard rules (from the owner's brief)

- No backend, no database, no API, no prices, no cart. Price is "on request"; every CTA is a `wa.me` link.
- All copy comes from `src/assets/data/*.json`. Changing a phone number, category name or hero line must never need a code change. Don't hardcode business text in templates; add a JSON field instead.
- Don't invent marketing claims. Missing copy goes in JSON as a string starting with `TODO`. `isSet()` in `content.service.ts` treats `TODO...` as empty, and templates hide it.
- Images load only when needed. Category pages must use virtual scrolling.
- The design follows the Figma file `SHwjHxNJ36O8hEj4ONkFdJ` (node `2:2`, "Landing / Desktop 1440"). Tokens in `src/styles/_tokens.scss` match it, except `--c-wa` and `--c-gold-text`, which were darkened for WCAG contrast. Keep the decorative `--c-gold` off text.

## How data flows

- `ContentService.init()` runs in `provideAppInitializer` and loads `site`, `nav`, `categories` and `catalog/index.json` into signals. Components read them synchronously (`content.site()`).
- Page data (`home.json`, `about.json`, `catalog/<slug>.json`) loads through route resolvers in `app.routes.ts` and reaches components as `input.required()` via `withComponentInputBinding()`.
- During prerender, HttpClient fetches of `/assets/data/...` are served from the build output. The HTTP transfer cache embeds the responses in the HTML, so the browser does not refetch.
- `app.routes.server.ts` imports `categories.json` directly for `getPrerenderParams`, so a new category is prerendered automatically.

## Image pipeline (scripts/build-images.mjs)

- Saree codes are `<category code>-<NNN>`, persisted in `codes.lock.json` (key `slug/filename`). Never renumber existing entries; customers quote these codes on WhatsApp. New files get `max + 1`.
- Each photo produces `<code>-400.webp`, `<code>-800.webp` and `<code>-800.jpg`, plus a 16 px base64 blur stored in the catalog JSON.
- Category covers come from `raw-images/00 Collections Page (category covers)/<cover>`. Site images come from `site-images.json`; file names are `<id>-<width>.<fmt>`, or `<id>-h<height>.webp` for logos.
- The pipeline is incremental by mtime, so delete outputs in `public/img/` to force regeneration.
- `excludeFiles` defaults to the logo `cropped-datt-1.png`, which exists in every folder.
- The hero source photo is only 480 px, so `hero-main-800.webp` is actually 480 px wide. That is expected.

## Performance architecture (don't regress)

- **Home hydration:** only the hero hydrates eagerly. The rest is incremental hydration:
  - Press, how-to, why, reviews, story and the final CTA use `hydrate never` (pure links and text).
  - Collections chips and the map use `hydrate on interaction`.
  - Footer: `hydrate never`. Announcement bar and floating button: `hydrate on idle` (in `app.html`).
  - Adding an Angular event or effect inside a `hydrate never` block silently won't work after a full page load.
- **Category grid:** the prerender renders the first `STATIC_TILES` (12) as a plain grid with `fade=false`, so it doesn't wait for JS. In the browser, `saree-grid` switches to `cdk-virtual-scroll-viewport scrollWindow` inside `requestIdleCallback`. The static grid is overlaid and then removed after two animation frames, so nothing flashes.
- **Rows and columns:** columns are 2 / 3 / 4 / 5 at container widths 600 / 960 / 1280, from a ResizeObserver. The static grid mirrors these with `@container` queries, so keep both in sync. Row height is `tileWidth + gap`.
- **Lightbox:** it opens through the CDK `Overlay` with the block scroll strategy and loads one 800 px image, then preloads only the previous and next images. The `?saree=CODE` query uses `Location.replaceState`, not `router.navigate`, because a router navigation would scroll the page to top.
- **Fonts:** the hero fonts (Playfair 600, Inter 400) are preloaded on the home page only, injected by the postbuild script. On category pages a font preload delays the first thumbnails (the LCP element), so don't add it there.
- **No `text-wrap: balance`:** it was removed because it measurably increased style and layout time on mobile.
- **Lighthouse on this PC:** the machine benchmarks around 640, so the default 4x CPU slowdown over-throttles. Use `--throttling.cpuSlowdownMultiplier=2` for calibrated local numbers, and PageSpeed Insights for the real ones. Run more than once; results are noisy.

## WhatsApp photo previews

- `wa.me` can only prefill text; it cannot attach an image. The item template in `site.json` therefore contains `{link}`, which becomes `<origin>/p/<CODE>`.
- `build-sitemap.mjs` writes one tiny page per saree at `/p/<CODE>/index.html` (570 pages). Each has `noindex`, an `og:image` of the 800 px JPEG, and a meta refresh to `/collections/<slug>?saree=<CODE>`.
- WhatsApp reads the `og:image` and shows the actual saree photo in the link preview.
- Those pages contain an `__ORIGIN__` placeholder. nginx replaces it at serve time with `$public_scheme://$http_host` (`sub_filter` in the `/p/` location; `X-Forwarded-Proto` is honoured behind Caddy). So previews work on the VM IP:port and on the domain without a rebuild.
- `WhatsAppService.absolute()` uses `location.origin` on public hosts and `seo.siteUrl` on localhost or LAN addresses. Photo links therefore never point at localhost.
- Previews only render when the site is reachable from the internet. Test them on the server, not with `npm start`.
- **The actual photo is attached by `core/photo-share.service.ts`** through `(click)="ask($event)"` on the tile pill and the lightbox button:
  - Touch devices: `navigator.share({ files: [jpg], text })` opens the share sheet (WhatsApp, then the shop chat).
  - Laptops: the photo is copied to the clipboard as PNG, then the `wa.me` chat opens, and `<app-toast>` tells the customer to press Ctrl+V.
  - Otherwise the anchor's `wa.me` href is used.
- **Both APIs need a secure context (HTTPS or localhost).** On `http://IP:port`, browsers hide them, so only the text and link are sent. The site must be on HTTPS for photo attachment to work for customers.

## SEO

- `SeoService.update()` sets the title, description, robots, canonical, Open Graph, Twitter and JSON-LD tags. The `ClothingStore` block is on every page, plus page-specific blocks.
- Category pages add a `BreadcrumbList` and an `ItemList` of the first 12 items as `ImageObject`.
- The alt text pattern is `sareeAlt()` in `saree-grid.component.ts`.
- `site.json` → `seo.siteUrl` drives canonical URLs and both sitemaps.

## Deployment gotchas (learned the hard way)

- **CSP:** `csp.conf` is generated by `build-sitemap.mjs` with sha256 hashes of Angular's inline scripts and the stylesheet `onload` handler.
  - After changing anything that alters inline scripts (hydration or event-replay config), rebuild; the hashes update automatically.
  - Test it with a CSP-enabled server before assuming it works.
- **nginx regex:** any nginx regex containing `{` or `}` must be quoted, or nginx exits with `pcre2_compile() failed`. The container then loops in `Restarting (1)`.
- **nginx config details:**
  - No IPv6 `listen` line: it fails on hosts with IPv6 disabled.
  - The `nginx-unprivileged` image listens on 8080 and runs as non-root.
  - `add_header` in a location drops inherited headers, so every location must `include /etc/nginx/snippets/headers.conf`.
- **Docker build:** it uses `node:24-alpine` (npm 11), matching the npm that wrote `package-lock.json`. `node:22` (npm 10) fails `npm ci` with missing `@emnapi/*`.
- **Docker and nginx aren't available on the dev PC,** so config changes can't be tested locally. Read nginx config changes carefully and say they are untested.
- **Linux file names:** names are case-sensitive on Linux. `folder` and `cover` values in `categories.json` must match the files exactly.

## Environment notes (Windows dev PC)

- **PowerShell 5.1 is the default shell.**
  - `$home` is reserved; don't use it as a variable.
  - `Set-Content -Encoding utf8` writes a BOM, which breaks JSON. Use `[IO.File]::WriteAllText` or Node to write files.
  - Here-strings passed to `git commit -F -` don't pipe. Write the message to a file and use `git commit -F <file>`.
- **npx:** `npx -y <pkg>` hit `ECOMPROMISED` cache errors; install tools into a scratch folder instead.
- **GitHub:** the remote is the private repo `https://github.com/satwikdivate/PK-Guled.git`, branch `master`. The GitHub CLI `gh` is installed but not authenticated.
- **Git commits:** commit or push only when the user asks.

## Conventions

- Standalone components, `ChangeDetectionStrategy.OnPush`, signals, `input()` and `output()`, and the new control flow (`@if`, `@for`, `@defer`).
- Small components use inline templates and styles. Larger pages (home, category-page) have separate `.html` and `.scss` files.
- Global classes `.btn` (`--wa`, `--outline`, `--primary`, `--light`, `--outline-light`, `--lg`, `--xl`), `.chip`, `.container`, `.section`, `.eyebrow`, `.lead` and `.visually-hidden` live in `src/styles/_base.scss` and `_typography.scss`. Reuse them rather than restyling.
- Browser-only work goes in `afterNextRender`. Use `storage` from `core/platform.ts` for localStorage, because it is wrapped in try/catch.
- Use `siteImg(id, width)` and `siteLogo(id, height)` from `core/platform.ts` for site image paths.
- Component style budget is 16 kB (warning) and 24 kB (error); initial bundle is 450 kB raw (warning). The current initial transfer is about 105 kB gzipped, and the target is under 180 kB.
